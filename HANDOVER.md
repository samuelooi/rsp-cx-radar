# Handover — RSP CX Radar

Written for: the next developer taking over this codebase, and the RSP BIM
team who will run it. Dated 18 September 2026. The wiki in `wiki/` goes into
each area in depth; this page is the map.

## What the tool is

A browser-only viewer and checker for CORENET X IFC-SG submissions. It loads
one or more IFC files locally (nothing is uploaded), indexes the elements the
IFC-SG mapping cares about, lets the user query any mapped component or
property in 3D, runs authority checks (IFC values, URA, geo-referencing, space
geometry, BCA placeholder), fixes last-mile property gaps in the IFC, exchanges
issues with the CORENET X Model Checker through BCF, and prints a submission
readiness report.

There is no build step and no Node. Everything is ES modules served by
`tools/serve.ps1` (or any static host), with three.js and web-ifc from unpkg.

## Large models (October 2026)

IFCs of 150 MB or more now open with That Open Fragments 3.4.7 instead of
web-ifc-three; smaller files keep the old path. See README → Large models for
how it behaves, and `poc/fragments/HANDOVER.md` and `RESULTS.md` on branch
`claude/fragments-poc` for why, the test bench and the measurements.

- **three.js went from 0.158 to 0.182** for everyone (Fragments needs it).
  web-ifc-three 0.0.126 and web-ifc 0.0.36 still drive small files and work on
  0.182; Fragments gets web-ifc 0.0.77 through an import-map scope.
- **One index for both paths.** The worker runs `buildIndex` itself, under web-ifc
  0.0.77. Two value shapes differ between the versions and are now read either
  way in `ifc-index.js`: the type tag (`label` vs `name`) and compound angles
  (site latitude/longitude). On a test model the checks give identical results
  either way; only the model's ground extent differs by 1 m² in 13,185 m²
  (tessellation).
- **Both engines share one scene and datum.** A large model's own coordination
  matrix is mapped onto the viewer's (`_placeFragments`); the same file opened
  both ways lines up within 8 mm.
- **Picking on large models is asynchronous** (Fragments raycasts in its
  worker). The viewer raycasts on pointer move and keeps the latest answer for
  the synchronous callers (`pickElement`, `raycastFace`, `elementTriangles`);
  clicks wait for an exact answer. Measuring and the section preview may
  therefore lag a frame on large models.
- Not done: conversion progress inside a
  geometry class, profiling the 590 MB conversion's geometry stage.

## What changed in the September 2026 session

In order, with the reason for each:

1. **Stair, roof and curtain-wall highlighting.** Revit exports these as
   geometry-less containers whose parts carry the triangles. The index now
   records aggregated parts for any such element and the viewer colours, hides
   and measures through them. Clicking a stringer resolves to its stair.
2. **Forma-style controls.** Left drag orbits, right and middle pan, wheel
   zooms. Section cuts are placed by clicking a face, snapped to the nearest
   world axis, and slid by dragging their handle.
3. **Flat query bubbles.** One bubble per component regardless of authority;
   one flat, deduplicated property list.
4. **Project settings file** (`<code>.ifcsg-project.json`). Gateway,
   authorities in scope, check selection, every check input (cadastral lot
   embedded), preset ticks, expected model files, hand-edit log. Save through
   the native picker, open by drop, restore from the recent list.
5. **IFC editing.** Fix or set a property, add a missing set, move a property,
   rename a storey, bulk-set from the legend. Byte-exact patch export with
   clone-on-shared, validated by web-ifc before download.
6. **BCF issues.** Import Model Checker results, edit status and comments,
   raise topics with camera and snapshot, turn findings into topics, export.
7. **Readiness report.** A PDF, written natively, with a strict verdict, the
   project context, per-check and per-rule results, outstanding failures,
   hand edits and a declaration.
8. **Space geometry check.** The community IFC Space Geometry Checker's one
   condition (IfcSpace without a representation) as a check module, with its
   columns and CSV.
9. **Study of the CORENET X Model Checker MVP guide**, mapping its schema and
   quality checks onto ours (see the wiki's Roadmap page).
10. **Model records in the project file** (format version 2). Every run stores
    per model: its identity, the dashboard quantities it contributed, each
    check's result and its findings. A submission can therefore be checked one
    file at a time on a machine that cannot hold them all, and the project
    still totals the whole thing. Records match files **by content, not by
    name**: a 256-hash sketch of the model's element GlobalIds, with the
    spatial GUIDs as corroboration. The panel labels each model as recorded,
    renamed, re-issued, not recorded or not loaded, and a rename is accepted
    with one click. See `js/model-id.js` and the wiki's Project file page.

There is no unit test runner. Verification is headless Chrome driving the real
app against real submission files, through a synthetic drop event and a debug
getter appended to a scratch copy of `app.js`. The wiki's Testing page has the
recipe and the traps. Results from this session:

## Known limits and decisions

- Edits live in the IFC copy only. The next Revit export overwrites them. The
  panel and the report both say so.
- A geometry-less space cannot be coloured. Its row opens the inspector.
- Value presets are written by hand in `data/value-presets.json`; the app only
  reads them. Ticks are session state, saved and restored by the project file.
- BCF viewpoints assume metres and the IFC project coordinate system, mapped
  through the viewer's coordination matrix. Viewpoints from other tools that
  use different conventions may land off target.
- The report's verdict is strict: any failure in any selected check means not
  ready. Checks not selected are listed as not run so the scope is explicit.
- Running the checks with no project open creates an untitled one to hold the
  records, so leaving the page then prompts to save. That is deliberate: the
  results are worth keeping and the chip invites naming the project.
- The cross-file rules (level consistency, coordinate alignment) still read
  only the models open at the time. The records now carry what they need;
  feeding them a federation view is the next step. See the Roadmap.
- The check-only (no geometry) load path was designed but not built.

## Running it

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080
```

Then open <http://localhost:8080>. The machine used for development has no
Node; the execution-policy flag is needed for the server script.
